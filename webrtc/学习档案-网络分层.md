## 已确认知识清单
- 三种分层对照：OSI 七层 / 五层（教材）/ TCP/IP 四层；四层把物理+链路合为"网络接口层"，七层的表示层、会话层并入应用层
- 分层是概念模型，实际协议不一定对号入座（DTLS/SRTP、ICE、SCTP over DTLS over UDP 都是跨层叠加的例子）
- 物理层：比特流 ↔ 电/光/电磁信号，只管 0/1 能否传过去，不懂含义、不知边界
- 数据链路层：把 IP 数据报封装成帧（帧头含 MAC 地址、帧尾含 CRC）；接收方做帧定界 + CRC 校验，错帧丢弃；在相邻节点间传输（一跳，hop-by-hop）
- 网络层：靠 IP 地址和路由，跨多跳把分组从源主机送到目的主机（主机到主机）；尽力而为，可能丢包、乱序、重复；IP 首部校验和只管首部，出错即丢弃
- 传输层：进程到进程（端到端），靠端口号区分同一主机上的进程
- 各层数据单位：应用层-报文；传输层-TCP 报文段 / UDP 用户数据报；网络层-IP 数据报/分组；链路层-帧；物理层-比特
- TCP 面向字节流，不保留消息边界，按 MSS 切报文段（以太网约 1460 字节）；消息边界需应用自己约定
- UDP 面向报文，一个应用报文原样封成一个数据报；最大约 64KB，超 MTU 会在 IP 层分片、丢一片全作废，所以应用通常自己切成约 1200 字节
- TCP 三次握手只负责建立连接、同步初始序号；可靠性来自序号 + ACK + 超时重传 + 校验和；另有流量控制、拥塞控制
- UDP：无连接、不确认、不重传、不保序；有校验和，出错丢弃但不补；"不可靠"≠"差"
- 传输层的"端" = 套接字 socket =（IP 地址, 端口号），端口只在一台主机内有意义
- 一条 TCP 连接由四元组（源IP, 源端口, 目的IP, 目的端口）唯一确定，加协议即五元组；因此服务器一个 443 端口可同时服务大量客户端
- 路由器只处理到网络层，不解析 TCP/UDP 首部、不参与确认重传——"端到端"的另一层含义；NAT 是例外，它改写 IP+端口
- 与 WebRTC 的关联：视频帧由 RTP 打包器切成约 1200 字节的包走 UDP；丢包由应用层 NACK/FEC/跳过处理；NAT 改写 IP:端口，所以需要 ICE/STUN/TURN 找到对方公网上的"端"

## 校准记录
用户自述理解中出现过的偏差（已纠正，复习时重点抽查）：
1. 把"端到端"安在网络层——实际网络层是主机到主机，端到端是传输层
2. 以为传输层的数据单位也是"完整的原始报文"——TCP 是字节流切段，UDP 才保留报文边界
3. 以为 TCP 可靠性来自三次握手——实际来自序号/ACK/重传/校验和
4. 链路层说成"把数字信号整合为帧""点到点"——应为"把分组封装成帧""相邻节点间（一跳）"
5. 以为"端"只指端口——实际是 IP + 端口
类比锚点：IP 地址 = 楼号，端口号 = 门牌号（接得住）
